# Training Diagnostics Plot Guide

This guide explains the plots generated by:

```text
CNN/analysis/plot_training_diagnostics.py
```

The script reads the structured files produced by diagnostics-enabled training and writes PNG files into the selected output directory.

Example:

```bash
python3 CNN/analysis/plot_training_diagnostics.py \
  --input results/<experiment>/<run> \
  --output-dir results/<experiment>/<run>/plots
```

The plotting backend is non-interactive, so the command works on cluster nodes without a display server.

## How To Read File Names

For ordinary or final training, plots usually have names such as:

```text
final_training_validation.png
final_gradient_depth.png
final_parameter_update_ratio.png
```

For cross-validation, the prefix identifies the numeric candidate and fold:

```text
candidate_000_fold_001_training_validation.png
candidate_000_fold_001_gradient_depth.png
```

Candidate and fold indices are zero-based.

The script may also generate plots with a `run_` prefix when the input directory itself is a single run directory.

## Important Axis Rule

Some plots use two different metrics with two different y-axes. Always read the axis label and color before comparing values.

In particular:

- Blue training-objective curves use the left y-axis.
- Brown validation-MSE curves use the right y-axis.
- Their visual heights are not numerical comparisons because the axes have different scales and units.

## 1. Training and Validation Metrics

File pattern:

```text
*_training_validation.png
```

### What It Shows

This figure contains two curves versus epoch:

- Training SIMM objective
- Validation physical-unit MSE

The training objective is read from:

```text
epoch_metrics.csv: train_objective
```

The validation curve is read from:

```text
epoch_metrics.csv: validation_physical_mse
```

### Axes

- x-axis: completed epoch
- left y-axis: SIMM training objective
- right y-axis: physical validation MSE

### Interpretation

Use the blue curve to see whether the optimization objective decreases on training data.

Use the brown curve to see whether prediction error on the validation set improves.

Typical patterns:

| Pattern | Possible interpretation |
|---|---|
| Both curves decrease | Training is improving and validation follows it |
| Training decreases, validation increases | Possible overfitting or distribution mismatch |
| Both remain high | Model may be underfitting, poorly initialized, or using unsuitable hyperparameters |
| Training decreases sharply, validation changes little | The model is fitting training data without improving generalization |

The two curves should not be subtracted. SIMM and physical MSE are different quantities.

### Missing Points

If validation was not evaluated at an epoch, the validation CSV field is empty and no validation point is plotted for that epoch.

Cross-validation defaults to validation every 10 epochs. For a short run where every epoch should appear, use:

```bash
--validation-interval 1
```

## 2. Gradient Norm Versus Depth

File pattern:

```text
*_gradient_depth.png
```

### What It Shows

The figure shows the epoch RMS L2 norm of synchronized global gradients across trainable layers.

Each line represents one epoch.

The data comes from:

```text
gradient_norms.csv
```

The plot uses rows where:

```text
parameter_scope = all
```

This combines weights and biases at the layer level.

### Axes

- x-axis: stable model layer index
- y-axis: epoch RMS gradient L2 norm
- y-axis scale: logarithmic

Zero values are replaced by a small plotting epsilon before logarithmic display. This changes only the visualization of zero, not the stored CSV value.

### Important Layer-Index Detail

The x-axis is the stable index in the complete model execution order, not a consecutive activation or trainable-layer counter.

For the baseline model, indices may look like:

```text
0 Conv2D
1 Activation
2 Flatten
3 Concatenate
4 Dense
5 Activation
6 Dense
7 Activation
8 Dense
```

Therefore gaps in layer indices are expected.

### Interpretation

- Large values near early layers may indicate strong gradients entering the feature extractor.
- Large values near the output may indicate concentration of learning in the head.
- Very small values across deep layers may indicate vanishing gradients.
- Extremely large values may indicate unstable gradients or aggressive loss scaling.
- Compare epochs to see whether gradient flow stabilizes during training.

The plotted metric is measured after MPI weighted gradient synchronization and before clipping or the optimizer update.

## 3. Parameter Update Ratio Versus Epoch

File pattern:

```text
*_parameter_update_ratio.png
```

### What It Shows

One line is plotted for each trainable layer using the actual parameter update ratio:

```text
||parameters_after - parameters_before||_2
------------------------------------------------
max(||parameters_before||_2, 1e-12)
```

The source file is:

```text
parameter_update_ratios.csv
```

The plot uses:

```text
parameter_scope = all
mean_ratio
```

### Axes

- x-axis: epoch
- y-axis: mean actual update ratio
- y-axis scale: logarithmic

### Why This Is Not Learning Rate Times Gradient

The ratio is measured around the real optimizer call. It includes:

- Gradient clipping
- Adam first and second moments
- Adam bias correction
- Weight decay
- Adam epsilon
- The actual parameter values before and after the update

It is therefore a direct measurement of how much each layer's parameters moved relative to their size.

### Interpretation

- High ratio: that layer is moving substantially relative to its current parameter magnitude.
- Low ratio: the layer is changing slowly.
- A declining ratio can indicate optimizer settling.
- A sudden spike can indicate a large gradient, a near-zero parameter denominator, or a change in optimizer behavior.

Check `near_zero_denominator_steps` and `mean_pre_update_norm` before interpreting a large ratio as instability.

Separate weight and bias scopes remain available in the CSV even though the default plot uses the combined layer scope.

## 4. Pre-Activation Histograms

File pattern:

```text
*_pre_activation_histograms_epoch_XXXX.png
```

### What It Shows

These histograms show the tensor entering each activation function during the selected training epoch.

The source rows use:

```text
activation_histograms.csv: phase = pre_activation
```

### Axes

- x-axis: pre-activation value
- y-axis: global population count

Each subplot corresponds to one activation layer.

### Interpretation

For ReLU or LeakyReLU:

- A large concentration below zero may indicate many units being suppressed or attenuated.
- A distribution concentrated near zero may indicate weak signal propagation.
- A very wide distribution may indicate exploding activations.

For Tanh or Sigmoid, large magnitudes may indicate saturation before the nonlinear function is applied.

The histograms aggregate all training batches processed during the epoch.

## 5. Post-Activation Histograms

File pattern:

```text
*_post_activation_histograms_epoch_XXXX.png
```

### What It Shows

These histograms show the tensor returned by each activation function during the same forward passes used for training.

The source rows use:

```text
activation_histograms.csv: phase = post_activation
```

### Interpretation

Compare pre- and post-activation plots for the same layer and epoch:

- ReLU should remove negative values.
- LeakyReLU should retain a scaled negative branch.
- Tanh should produce values approximately in `[-1, 1]`.
- Sigmoid should produce values approximately in `[0, 1]`.

Unexpected values can indicate an implementation issue, a mislabeled layer, or numerical instability.

## 6. Activated Variance Versus Depth

File pattern:

```text
*_activated_variance_depth.png
```

### What It Shows

This figure plots post-activation population variance across activation layers for selected epochs.

The source rows use:

```text
activation_statistics.csv: phase = post_activation
```

### Axes

- x-axis: stable model layer index, activation layers only
- y-axis: post-activation population variance
- one line per selected epoch

The x-axis can contain gaps. For example, `1`, `5`, and `7` may be present while `2`, `3`, `4`, and `6` are absent because those are Flatten, Concatenate, or Dense layers rather than activation layers.

### Interpretation

- Similar variance across depth may indicate stable signal scale.
- Variance shrinking toward zero can indicate vanishing activations.
- Variance growing strongly with depth can indicate activation scale growth.
- Differences between epochs show how activation scale evolves during training.

The values are globally aggregated across MPI ranks, not taken from rank zero's local batch.

If variances span several orders of magnitude, the script may use logarithmic y scaling.

## 7. Activated Variance Versus Epoch

File pattern:

```text
*_activated_variance_epochs.png
```

### What It Shows

This figure tracks post-activation variance over time.

Each line represents one activation layer.

### Axes

- x-axis: epoch
- y-axis: post-activation population variance

The layer label includes the stable model layer index.

### Interpretation

- Stable lines suggest consistent activation scale.
- Declining lines may indicate neurons becoming inactive or signal attenuation.
- Rising lines may indicate increasing activation magnitude.
- Abrupt changes may align with training instabilities, learning-rate changes, or optimizer transitions.

This plot answers: “How does one activation layer's variance change over training?”

The depth plot answers the complementary question: “How does variance differ across layers at one epoch?”

## 8. Activated Variance Heatmap

File pattern:

```text
*_activated_variance_heatmap.png
```

### What It Shows

The heatmap combines both dimensions:

- One axis: epoch
- Other axis: stable activation-layer model index
- Color: post-activation population variance

### Axes

- x-axis: activation layer's stable model index
- y-axis: epoch
- colorbar: variance or `log10(variance)`

The script automatically uses log10 color values when the positive variances span a sufficiently large range.

### Interpretation

Look for:

- Vertical bright bands: a layer consistently has high variance.
- Vertical dark bands: a layer consistently has low variance.
- Horizontal changes: a training epoch affects many layers simultaneously.
- Expanding bright regions: activation scale may be growing.
- Expanding dark regions: activation signal may be collapsing.

Missing x positions are expected for non-activation model layers.

## 9. Learning Rate Versus Epoch

File pattern:

```text
*_learning_rate.png
```

### What It Shows

The effective learning rate recorded in `epoch_metrics.csv` for each epoch.

### Axes

- x-axis: epoch
- y-axis: effective learning rate

### Interpretation

For the current Adam implementation, the learning rate is constant, so the plot should be horizontal.

For an optimizer with a schedule, this plot shows the epoch-level schedule. If the optimizer reports per-step scheduling, the corresponding detailed values are in `learning_rate_steps.csv`.

## 10. Cross-Validation Fold Comparison

File pattern:

```text
cv_fold_comparison_topology_XX.png
```

### What It Shows

Each line represents the validation physical MSE history of one CV fold.

The source is each fold's:

```text
```

### Axes

- x-axis: epoch
- y-axis: validation physical MSE
- one line per fold

### Interpretation

- Similar fold curves indicate consistent behavior across splits.
- One consistently worse fold may contain more difficult samples.
- Large variation between folds indicates sensitivity to the data split.
- Curves improving together suggest robust learning.

The plot does not select the candidate. Candidate selection remains the sample-weighted mean physical validation MSE recorded in `cv_summary.csv`.

### Topology Separation

Candidates with different model-layer topologies are not aggregated into the same comparison plot. The script groups them using the ordered layer metadata stored in each `metadata.json`.

This prevents a layer-depth comparison from becoming misleading when candidates have different numbers or types of layers.

## Reading the Raw CSV Files

The plots are summaries. For precise values, use the CSV files directly.

Important files:

```text
epoch_metrics.csv
gradient_norms.csv
parameter_update_ratios.csv
activation_statistics.csv
activation_histograms.csv
learning_rate_steps.csv
cv_summary.csv
```

CSV fields may be empty when a metric was not evaluated at that epoch. In particular, validation MSE is empty when the epoch is not a validation checkpoint.

## Common Misinterpretations

### Comparing SIMM and Physical MSE Numerically

Do not compare their magnitudes directly. SIMM is a standardized training objective with a physics penalty. Physical MSE is prediction error in physical units.

### Expecting Every Model Layer in Activation Plots

Only `ActivationLayer` instances produce activation statistics. Conv2D, Dense, Flatten, and Concatenate do not automatically produce activation rows.

### Treating Stable Model Indices as Activation Ordinals

An activation at model index 7 is not “the eighth activation.” It is the layer at position 7 in the complete execution order.

### Reading Visual Height Across Twin Axes

Training objective and validation MSE use separate axes. A point at the same visual height does not mean the two values are equal.

### Interpreting Histogram Edge Counts as a Detailed Tail Distribution

The histogram is fixed to a configured range. Values below the minimum and above the maximum are placed in edge bins. Inspect the exact minimum and maximum in `activation_statistics.csv`.

### Treating a Single Short Run as a Reliable Tuning Result

One or two folds and a few epochs are useful for checking the pipeline and visualizations. They are not enough for a robust scientific conclusion.

## Recommended Plot Review Order

For a new run, inspect plots in this order:

1. Training/validation curves for optimization and generalization behavior
2. Learning rate for schedule correctness
3. Gradient depth plot for vanishing/exploding gradients
4. Update-ratio plot for actual optimizer movement
5. Pre/post histograms for nonlinear behavior and saturation
6. Variance-versus-depth plot for one-epoch signal distribution
7. Variance-versus-epoch plot for temporal stability
8. Variance heatmap for combined depth/time patterns
9. CV fold comparison for split sensitivity

Always combine plots with the raw metadata and CSV values before changing a model or optimizer.
